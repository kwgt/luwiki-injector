# luwiki ページインジェクター 要件定義書

## 1. システム概要

- `kwgt/luwiki` に接続し、指定されたデータソースの内容でページ作成を行う。
- 初期用途はWikiサーバー立ち上げ時の初期ページ用意、およびAIエージェント向けハーネス等の取り込みとする。

## 2. ページソース

### 2.1 ページソース仕様

- ページ構造をファイルツリーで表す。
- 四入力方式に共通して、ソース最上位の小文字 `root/` ディレクトリ配下だけを入力対象とする。ZIPの最上位、または選択したGit commit/worktreeの最上位を基準とする。
- 先頭の `root/` 一段を取り除いた相対名を、指定prefix（既定 `/`）の配下へ投影する。root外のREADME等はページとして取り込まない。rootがない、またはdirectoryとして扱えない場合は入力エラーとし、ソース最上位へfallbackしない。
- ZIPでは明示directory entryがなくても `root/a.md` 等からrootの存在を認識する。root内に対象Markdownがない場合は必要な安全検査成功後に正常な空集合とする。取込root自体のWikiページは生成しない。
- `.md` ファイルをWikiページに投影する。ファイル内容はUTF-8本文としてそのまま登録し、拡張子 `.md` はページ名に含めない。
- root内の拡張子だけの `.md` および `dir/.md` のように、拡張子を除いたファイル名が空になる入力は、入力エラーとして拒否する。
- rootが存在し、全入力の必要な安全検査に成功したうえで、root内の小文字 `.md` 通常ファイルが1件もない場合、共通検証は空のページ集合を正常な結果として返す。
- ディレクトリはページパスを表す。ディレクトリに対応するMarkdownファイルがない場合、そのディレクトリだけを理由に親Wikiページを自動生成しない。
- 投入順序は親ページから子ページの順とし、同じ深さではページパスのUTF-8文字列の辞書順とする。

例えば、ソース内の `root/ワークエリア.md` は `/ワークエリア` に投影し、`root/ワークエリア/共通規範.md` は `/ワークエリア/共通規範` に投影する。prefixが `/取込先` なら、それぞれその配下となる。復旧用の入力参照は元の `root/` を含む名前を保持する。

### 2.2 ページソースの入力形式

- 通常ZIPおよびZIP64アーカイブ、ローカルGitリポジトリ、HTTPSリモートGitリポジトリ、GitHubの `owner/repo` 指定を扱う。
- 初期版のGitHub privateリポジトリ取得はHTTPSトークンを用いる。SSHおよびcredential helperによるGit認証は初期版の対象外とする。
- HTTPSリモートGit URLはホストとリポジトリパスを許容し、userinfo・query・fragmentは拒否する。認証情報はURLへ埋め込まない。
- ローカルGitの既定入力はコミット済みツリーとする。`--worktree` 指定時は、追跡済みファイルのステージ済み・未ステージ変更と、`.gitignore` 対象外の未追跡ファイルを含める。
- `--worktree` はブランチ、タグ、コミットの明示指定と併用しない。シンボリックリンクは拒否する。
- mainがあればmain、なければmasterを既定参照とする。GitHubのdefault branchやremote HEADを優先参照にしない。
- GitまたはGitHub入力では、ブランチ、タグ、コミットIDを明示指定できる。
- `.zip` の拡張子による自動判別は、小文字の `.zip` との完全一致とする。
- ローカルGitの自動判別対象はGit worktreeとし、bare repositoryは初期版の対象外とする。
- Gitサブモジュール（gitlink）は初期版の入力対象として展開せず、対象のコミットツリーまたはworktreeにある場合は入力エラーとして拒否する。

### 2.3 ZIPの文字コード

- ZIP内の各エントリ名の生バイト列を厳格なUTF-8として検証する。
- 非ASCII文字を含むエントリ名はZIP general purpose bit 11（UTF-8 flag）が設定されていなければならない。
- ASCIIのみのエントリ名にはbit 11を必須としない。

### 2.4 入力の禁止事項と検証

- ページパスとページプレフィクスに空白文字を含めてはならない。
- ページパス、ページプレフィクス、root内の対象Markdown本文は厳格なUTF-8として検証し、U+FFFD（置換文字）を含めてはならない。root外の本文はページ本文検証の対象外とする。
- 絶対パス先頭の `/` を除き、パス中の空セグメント、`.`、`..`、バックスラッシュ、制御文字、NUL、先頭または末尾の空白、連続スラッシュを禁止する。
- ZIPまたはGit入力のシンボリックリンク、パストラバーサル、重複する投影先ページパスを拒否する。
- root外をページ候補から除外しても、全ソースの名前・構造安全検査とZIP/Gitの全量上限は維持する。ページ件数・ページ本文上限はroot内の対象Markdownだけへ適用する。
- ページ件数、ページ本文サイズ、ZIPエントリ数、ZIP圧縮後サイズ、ZIP展開後サイズ、Git取得サイズ、処理時間、HTTP並列数に安全上限を設け、設定で変更可能にする。初期版の既定値と許容範囲は `CONFIG_SPECS.md` に定める暫定値とし、実際の初期ページ集・ハーネスを使ってOP5で再評価する。
- ZIP圧縮後サイズの上限は、ヘッダー、中央ディレクトリ、extra fieldを含むZIPファイル全体のバイト数に適用する。
- Git取得サイズの上限は、取得後の専用一時領域サイズに適用し、checkoutおよびWiki書き込み前に超過を拒否する。取得中は進捗を監視して協調停止を試みるが、通信と一時領域のサイズが一時的に上限を超える可能性は許容する。

## 3. サーバアクセスと認証

- Wikiページの操作はREST APIによって行う。
- Wiki HTTPのリダイレクトはGETを含め自動追従せず、3xx応答を単発操作の失敗として扱う。
- 既存Wiki本文・JSON・エラー応答には固定受信量上限を追加しない。逐次処理と既存の処理期限・取消で管理し、全量のメモリ保持を避ける。入力Markdownの `max_page_bytes` をWiki応答へ流用しない。
- 対象サーバURLの優先順位は次のとおりとする。
  1. CLI位置引数 `TARGET-SERVER`
  2. `LUWIKI_URL` 環境変数
  3. 設定ファイルの `server.url`
  4. 既定値 `https://localhost:8080`
- Wikiサーバー認証はBasic認証またはBearer認証をサポートする。同じ実行で両方式が同時に指定された場合は曖昧性エラーとする。
- 対象Wiki URLはHTTPまたはHTTPSでホストを必須とし、userinfo、query、fragment、ルート以外のパスを拒否する。空パスと `/` は同じ接続先として扱う。
- Wiki認証情報が完全に未指定の場合、およびBasicパスワードだけが指定された場合は起動エラーとする。
- 候補値は優先順位で採用した値だけを意味検証する。設定ファイルの読込・TOML構文・型・未知キーは、値の採用有無によらず検証する。
- Wiki認証情報の優先順位はCLI、環境変数、設定ファイル、条件付きTTY対話入力の順とする。対話入力はBasicユーザー名が指定済みでパスワードだけが不足している場合に限る。
- Basic認証の環境変数は `LUWIKI_USER` と `LUWIKI_PASSWORD`、Bearerトークンは `LUWIKI_TOKEN` とする。
- GitHubトークンは `GITHUB_TOKEN` 環境変数だけで受け付ける。GitHubトークンはWiki認証情報と区別する。
- CLIへの秘密情報直接指定について、プロセス一覧やシェル履歴に露出するリスクを警告する。
- 認証情報、Authorization情報、GitHubトークン、Git資格情報、ページ本文、ページロックトークンをログ、エラー、復旧情報に出力しない。

## 4. ページ作成と衝突処理

- 書き込み前に対象Wikiページの存在を確認する。
- ページが存在しない場合は新規作成する。
- 既存ページがある場合の動作は、`error`、`update`、`overwrite` から選択する。
- `error` は既存ページの本文が同一であっても無条件にエラーとする。
- `update` は既存本文と入力本文が同一なら書き込みを行わず、異なる場合は更新する。
- `overwrite` は既存本文と入力本文が同一なら書き込みを行わず、異なる場合は既存ページを削除した後に作成する。
- 初期版の同一判定はUTF-8バイト列の完全一致とする。BOM、改行コード、末尾改行を自動変換しない。比較方式は将来交換可能な責務とし、front matter等によるバージョン比較は初期版に含めない。
- `update` はロック取得後に本文を再取得して比較する。事前確認時から本文が変化していた場合は競合として処理全体を停止する。
- `overwrite` は削除直前にページIDと本文を再照合する。DELETE後に元ページを自動復元する機能は設けない。
- PUTまたはDELETEが500応答または応答状態不確定となった場合、同じ期限・取消境界が許す場合に状態を再照合する。目的状態が確認できても警告を出して最終終了コードを非0とし、応答コードだけから障害原因を断定しない。
- `overwrite` 中のDELETEが500となった場合、API再照合で削除済みと確定できたときに限り再作成へ進む。再作成の結果にかかわらず警告を出して非0終了とする。削除済みと確定できない場合、またはPOST以降の応答状態が不確定な場合は停止する。
- 不確定応答後の自動再送、自動再試行、自動ロールバックを行わない。新規作成POSTの応答喪失時も停止する。
- 複数ページ処理では1件の失敗時に全体を停止し、後続ページは未実行とする。既に成功したページを自動ロールバックしない。
- ページ別に成功、警告付き適用、失敗、未実行を識別して報告する。
- 復旧情報には旧ページID、パス、revision、入力参照、処理段階を含める。本文そのものは含めない。
- 取得からWiki操作まで同じ絶対期限・取消境界を共有する。期限または取消へ到達した後は、再照合・自分が保持する既存ロックの解放を含め追加HTTPを行わない。別の処理猶予を設けず、確定情報を報告して停止する。
- Wikiロックの期限はRFC3339で解析する。時計ずれ補正・猶予は設けず、期限形式が不正、または受信時点で期限切れなら停止する。
- 不確定応答後に期限・取消のため再照合できない場合、適用有無やロック状態を推測せず、不確定状態と判明した復旧情報を報告する。

## 5. 設定ファイル

- 設定ファイルで対象サーバURL、Wiki認証情報、ページプレフィクス、衝突モード、入力上限を指定可能とする。
- 設定形式、項目名、型、探索規則、優先順位、エラー動作は `CONFIG_SPECS.md` に定義する。
- GitHubトークンは設定ファイルに保存せず、`GITHUB_TOKEN` 環境変数のみで指定する。

## 6. 初期リリース範囲と品質基準

- 初期リリースはZIP、ローカルGit、HTTPSリモートGit、GitHub `owner/repo` の全入力方式と、`error`、`update`、`overwrite` の全モードを対象とする。
- LinuxおよびRust 1.92を初期検証基準とする。他OS対応と正式なMSRVは保証対象外とし、依存クレート確定後に別途判断する。
- SSH・credential helperによるGit認証、Markdown以外のアセット投入、自動ロールバック、原子的なoverwrite、front matterによるバージョン比較は初期版に含めない。

## 7. ログ

- ログ出力には `env_logger` を使用する。
